# AcrylicPanCollector ファームウェアオーバーレイ

## 概要

このディレクトリには、本プロジェクトが所有する収録・推論ロジックだけを置く。
インストール済みの`AIVibrationInference`サンプルにはDATA TECNOとROHMの著作物が含まれ、
プロジェクト全体に適用できる再配布ライセンスがないため、それらのファイルは
このリポジトリへコピーしない。

ファームウェアは収録用の全コマンドを持ち、そのうえで固定8クラスの推論セルフテスト、
12エリア推論、位置確率推論、現場キャリブレーションを提供する。PC側のデコーダは
`pc/acrylic_pan_monitor/protocol.py`である。COM3での検証結果は
`../../docs/ai-dummy-validation.md`にまとめてある。

## 動作モード

動作モードは`SET_MODE`（`0x15`）で選ぶ。モード変更は停止中だけ受け付ける。

| mode | 名称 | 送信内容 |
|---:|---|---|
| 0 | 収録 | `EVENT_DATA`（2,048サンプル） |
| 1 | 通常推論 | 12スコアの`AI_RESULT`に続けて`INFERENCE_EVENT`（512サンプル波形付き） |
| 2 | 低遅延インストゥルメント推論 | 12スコアの`AI_RESULT`のみ |
| 3 | 位置確率 | `POSITION_RESULT`のみ |
| 4 | 現場キャリブレーション | `CALIBRATION_RESULT`（[現場キャリブレーション（mode 4）](#現場キャリブレーションmode-4)） |

### 推論セルフテスト

`AI_SELFTEST`（`0x14`）は0〜7のテストケース番号1バイトを受け取る。`AI_RESULT`（`0x21`）は
固定セルフテストでは`<BBH8f`、12エリアのライブ推論では`<BBH12f`を返す。内容は
ケース番号、CPU側で求めたargmaxクラス、予約（0）、Solist-AIの生出力スコアである。

セルフテスト用の組込みモデルは入力128、隠れ層32、出力8で、hard sigmoid/MSEを使う。
αは公式Solist-AI Simulatorのseed-1モデルから取得した。α、β、8つの検定用入力は
すべてbfloat16で格納する。

### 通常推論（mode 1）

ライブ推論では、まずcase `0xFF`の12スコア版`AI_RESULT`（`0x21`）を送る。これにより
インストゥルメント側のクライアントは波形を待たずにクラスとスコアを受け取れる。
続いて`INFERENCE_EVENT`（`0x22`）を送る。内容はイベントのメタデータ、同じ推論クラスと
スコア、モデルに入力したZ軸生サンプル512点そのものである。

PCは表示用FFTをこのサンプルから計算する。そのため、強調表示するエリア、波形、
スペクトルは常に同じ打撃に属する。FFTは表示専用であり、time128 v1モデルの入力ではない。
通常の推論ページはmode 1を使い、波形を保持する。

### インストゥルメント推論（mode 2）

mode 2は優先度の高い簡易結果だけを送り、すぐに再アームする。波形とFFTの送信を
省く代わりに、連打の間隔を最短にする。

このモードでは再トリガ抑止をファームウェアが担う。`SET_CONFIG`（`0x12`）は
little endianのuint16で0〜500 msの間隔を受け付ける。この間隔内の打撃は、`AI_RESULT`を
送らず、LCDとLEDも変えずに再アームする。したがってブラウザへ届く結果は1つずつが
1回の発音イベントに対応し、ブラウザ上のエリア、音、LCD、3ビットLED表示は同じ
受理済み打撃を指す。

### 位置確率（mode 3）

mode 3は128-32-60のSolist-AIモデルを12出力ヘッド5つとして実行し、MCU上で温度0.05の
60通りsoftmaxを計算する。αは`ODL_Initialize`が生成する固定のseed-1射影であり、
配備するのは蒸留したβの重みだけである。

送信するのは`POSITION_RESULT`（`0x24`）で、正規化したfloat32の確率と、実測した
Solist、softmax、合計の各計算時間を含む。波形は送らない。PCはデバイスが生成した
分布を集計・描画するだけである。このモードは400 × 300 × 5 mmパネルとその実測60位置用である。

### LCDとLED表示

ライブ推論のたびに、ボードのLCDに分類したエリアの中心と、実測したモデル推論時間を
表示する。1行目は`X050 Y050 A01`の形式（mm単位の座標とエリア番号）、2行目は
`INFER 012.34ms`の形式である。12クラス分類は座標を回帰しないため、X/Yは選ばれた
100 mm角エリアの中心座標である。位置確率（mode 3）では最尤位置の座標を表示する。
LCD描画は簡易AI結果がUARTから送出された後まで遅らせ、発音までの遅延を保つ。

ボード上の3つのLEDは、0始まりのモデルクラスの下位3ビットを示す。物理的な左から右の
並びはLED1（MSB）、LED2、LED3（LSB）で、エリア1が`000`、エリア2が`001`、エリア8が
`111`となる。エリア9〜12は下位3ビットが1〜4と同じになるため、区別にはLCDを使う。
起動時のセルフテストでは、最初のライブ推論結果で置き換わるまで3つのLEDをすべて点灯する。

## 収録動作

- KX134のZ軸、25,600 samples/s、32 gレンジ（1024 LSB/g）
- ベンダの512サンプルダブルバッファを連続使用する
- ジャーク検出はブロック境界をまたいで継続する
- 64サンプル（2.5 ms）の循環プリトリガ履歴を持つ
- 収録モード: 2,048サンプル（80 ms）、うちトリガ後1,983サンプル
- 推論モード: 配備中のv1モデルが使う512サンプル（20 ms）を保持する
- センサはイベント全体がそろってから停止する
- APANバージョン1の`EVENT_CHUNK`、CRC32、COBSフレーミング、115,200 bit/s。
  2,048サンプルの収録は、個別に検査される512サンプルのチャンク4つとして送る
- 既定の生カウント閾値: ジャーク700、絶対レベル200、16サンプル以内の確認3000。
  5 mm板は3 mm板より立ち上がりが緩く、有効打撃の22.7%がジャーク1000〜1100 LSBに
  入るため、候補の閾値を700へ下げ、ノイズは確認条件（直前64サンプル平均から
  3000 LSB以上の振幅）で除外する。物理スケールでジャーク500とした場合は、生カウントの
  ノイズが感度に比例して下がらないため、静止状態で誤トリガした

コレクタは停止状態で起動する。`CAPTURE`はセンサブロックをちょうど1回開始し、
`EVENT_DATA`をキューに入れた後に停止状態へ戻る。そのためPC制御の繰り返し測定は
決定的になる。`START`は次の打撃収録をアームする。停止状態から`START`へ遷移するたびに、
古い履歴を消去して新しい64サンプルのリング履歴を充填し直す。PCは`EVENT_DATA`フレーム
全体をデコード・保存し終えてから次の`START`を送る必要がある。

## 通信プロトコル

### テキストコマンド

UART1は改行終端のASCIIコマンドを115200 8-N-1で受け付ける。

- `PING`は`PONG APAN/1`を返す
- `STATUS`は`STATUS IDLE`、`STATUS ARMED`、`STATUS TX`のいずれかを返す
- `CAPTURE`と`GET_STATIC`は`ACK CAPTURE`を返し、収録モードでは続けて2,048点のZサンプルを
  バイナリAPANの`EVENT_CHUNK`フレーム4つ（トリガインデックス0）で送る
- 未知のコマンドには`NACK UNKNOWN`を返す

コマンド応答は端末で診断しやすいようASCIIとする。波形は常に、PCモニタが受け取る
CRC保護付きのバイナリフレームで送る。

### バイナリコマンド

同じ操作をAPANバイナリ要求としても受け付ける。

| 要求 | ID | 内容 |
|---|---:|---|
| `HELLO` | `0x01` | 識別 |
| `STATUS` | `0x02` | 状態取得 |
| `START` | `0x10` | 打撃収録をアームする |
| `STOP` | `0x11` | 停止 |
| `SET_CONFIG` | `0x12` | mode 2の再トリガ抑止間隔（uint16、0〜500 ms） |
| `CAPTURE` | `0x13` | 強制収録（収録モードのみ） |
| `AI_SELFTEST` | `0x14` | 推論セルフテスト（ケース0〜7） |
| `SET_MODE` | `0x15` | 動作モード選択（停止中のみ） |
| `CALIBRATION` | `0x16` | 現場キャリブレーション操作（停止中のみ） |

デバイスからの主なメッセージは`ACK`（`0x70`）、`NACK`（`0x71`）、`AI_RESULT`（`0x21`）、
`INFERENCE_EVENT`（`0x22`）、`POSITION_RESULT`（`0x24`）、`CALIBRATION_RESULT`（`0x27`）、
`EVENT_DATA`/`EVENT_CHUNK`である。

`SET_MODE`のペイロードは0で収録、1で通常推論、2で低遅延インストゥルメント推論を選ぶ
（3、4は[動作モード](#動作モード)を参照）。`START`は打撃収録をアームし、収録モードでは
`EVENT_DATA`、推論モードでは`INFERENCE_EVENT`を送る。`CAPTURE`は収録モードでのみ受け付ける。

応答は要求のsequenceをそのまま保持する。`ACK`（`0x70`）は1バイトの要求タイプを含む。
`NACK`（`0x71`）は要求タイプと理由（1 busy、2 unsupported、3 invalid）を含む。

バイナリ`STATUS`のペイロードはlittle endianの`<BBHHIB>`で、状態、フラグ、サンプル数、
トリガインデックス、サンプルレート、動作モードの順である。状態は0 idle、
1 強制収録アーム中、2 送信中、3 停止である。

`STATUS.flags`は起動時のUIセルフテスト結果を示す。bit 0はLCDへの`test`描画成功、
bit 1、2、3はLED1、LED2、LED3の実際の出力状態である。したがって起動が正常なら
`flags = 0x0f`を返す。1行目に`test`を描画する前に、5 Vレギュレータと
LCDバックライトを有効にする。

## 現場キャリブレーション（mode 4）

キャリブレーションモード（`SET_MODE` 4）は、誘導に従って数打するだけで12エリア用βを
取り付け済みのパネルへ適応させる（`../../docs/odl-calibration-experiment-20260927.md`）。
OS-ELMの更新はAxlCOREのbfloat16による`ODL_StartTrain`ではなく、CPU上のfloat32で行う。
P（32 × 32）とβ（32 × 12）はfloat32の行としてボードのFRAMのアドレス100000以降に置く。
1打ごとにβをbfloat16へ丸めてAxlCOREへ書き戻す。追加するRAMは316バイトだけである。

`generated/apan_calibration_prior.h`は配備中のβに対する`P0 = 30 (G + I)^-1`を与える。
キャリブレーション1打は工場データ30イベント分に相当する。`apan_12class_model.h`を
変更したときは`python -m sim.odl_calibration_prior`で再生成する。起動時にファームウェアは
工場βのCRC32と事前分布側の値を比較し、一致しなければキャリブレーションを無効にする。

`CALIBRATION`（`0x16`）は操作と引数の2バイトを受け取り、コレクタが停止中のときだけ受け付ける。

| Op | 名称 | 効果 |
|---:|---|---|
| 0 | STATUS | 状態の報告のみ |
| 1 | BEGIN | mode 4のみ: 作業用β = 工場β、P = P0 |
| 2 | ARM | mode 4のみ: 1打分アームする。引数は学習するエリア0-11、確認のみなら`0xFF` |
| 3 | COMMIT | 作業用βをFRAMへ保存する。保存したβは毎回の起動時に読み込む |
| 4 | DISCARD | 作業用βを破棄し、保存済みまたは工場のβへ戻る |
| 5 | FACTORY_RESET | 保存済みキャリブレーションを無効にする |

受理した要求には`<BBBBHH>`でACKを返す。内容は要求タイプ`0x16`、操作、有効なβの出所
（0 工場、1 保存済み、2 作業用）、保存済みフラグ、保存済み打数、作業用打数である。
NACKの理由は1 busy、2 未対応の操作、3 不正な状態または引数、4 FRAM/キャリブレーション失敗である。

アームした1打の後、ファームウェアは現在のβで推論し、目標が与えられていればその打撃を
学習してから停止し、`CALIBRATION_RESULT`（`0x27`、`<BBBBHHII12f>`）を送る。内容は
目標（確認のみなら`0xFF`）、学習前の推論クラス、フラグ（bit 0 学習済み、bit 1 学習失敗）、
有効なβの出所、作業用打数、予約（0）、推論時間と学習時間（マイクロ秒）、12スコアである。
コレクタはPCが次の打撃をアームするまで停止したままである。

`python -m pc.acrylic_pan_monitor.calibrate --port COM3`は誘導付きのセッションを実行する。
各エリア1打の確認、5周の学習、再度の確認を行い、確認精度が下がらなかった場合だけコミットする。

保存済みキャリブレーションは推論モードとインストゥルメントモード（1と2）で使う。
位置確率モデル（mode 3）は別モデルであり、キャリブレーションの対象外である。

## ホストテスト

`tools/test-host.ps1`は、512サンプルのブロック境界ちょうどでのトリガを試験し、Cで生成した
パケットをPython版PC実装でデコードする。あわせて、RAMで代替したFRAMスタブに対して
`tests/test_calibration.c`を実行する。

## ビルドと書き込み

### 非公開LEXIDEプロジェクトの作成

PowerShellから実行する。

```powershell
.\firmware\AcrylicPanCollector\tools\install-overlay.ps1
.\firmware\AcrylicPanCollector\tools\build-private-project.ps1
```

インストーラはローカルにインストールされたサンプルを
`C:\Users\yamas\lexide\workspace_omega_v2\AcrylicPanCollector_private`へ複製し、複製側の
メインエントリポイントだけを置き換え、`S_AcrylicPan`を追加し、UART 115200を選択する。
既存の出力先は上書きせず、元の`AIVibrationInference`プロジェクトは編集しない。

### ビルド

ビルドスクリプトはEclipseもJavaも起動しない。生成済みmakeメタデータの非公開コピーを使い、
LEXIDE付属の`make.exe`とコンパイラツールを直接呼び出す。`make clean`は実行しないこと。
LEXIDEは`.res`コンパイラオプションファイルを生成物として扱うが、単純なmake呼び出しでは
再生成できない。生成されるイメージは
`...\AcrylicPanCollector_private\Debug\AIVibrationInference.hex`である（成果物名は
ベンダのビルドメタデータに由来する）。

作成済みのprivateプロジェクトを変更せずにビルドするときは、リポジトリ直下の
`scripts/build-firmware.ps1 -SourceProject <privateプロジェクト>`を使う。
`.local\firmware-build\<日時>`へ作業コピーを作り、最新のオーバーレイと`subdir.mk`を入れ、
足りないコンパイラ応答ファイル（`.res`）を`apan_inference.res`から補ってビルドする。

### 書き込み

リポジトリ直下の`scripts/flash-firmware.ps1`は、LEXIDEのROHM対応`openocd_arm.exe`を使い、
MCU-Link CMSIS-DAP経由でイメージを書き込む。ELFからFlash専用バイナリを作り、消去、
書き込み、全Flashバイトのベリファイを行った後、ターゲットをリセットして実行する。
代替手段として`tools/flash-pyocd.ps1`もある。

## 制約

### 送信中のサンプリング停止

エンコード後のイベント1つは約1.06 kBで、115200 8-N-1では約93 msかかる。
このフレームの送信中はサンプリングを止める。選ばれたイベントは保たれるが、
UART送信中に起きた打撃は収録の対象外である。
