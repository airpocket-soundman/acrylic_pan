QUICK STARTまず演奏する

初期セットアップ済みのラズパイを使う場合の手順です。初回導入は付録Aを先に行ってください。

STEP 01

接続する

板とフレームを安定して設置。センサ基板をラズパイへUSB接続し、モニター・スピーカーをつなぎます。

STEP 02

電源を入れる

周辺機器とラズパイの電源を入れます。自動で「演奏」画面が開き、「センサ接続中」になるのを待ちます。

STEP 03

叩いて確かめる

音量を下げてから、板のエリア中心を軽く1打。音が鳴り、対応エリアが光ることを確認して演奏します。

STEP 04

安全に終了する

「管理」→「ラズパイの電源を切る」を3秒長押し。終了案内に従い、アクセスLEDの点滅が止まってから電源を外します。

電源ケーブルをいきなり抜かないでください。収録データや保存中の設定が破損する原因になります。認識が不安定なときは強く叩き続けず、支持状態を確認してから現場キャリブレーションを行います。

01 / OVERVIEWSolistpanについて

Solistpanは、1個の加速度センサでアクリル板の振動を読み取り、叩いた位置を音へ変換する楽器です。板の振動の違いをSolist-AIが判別し、60地点の位置確率を12エリアにまとめて発音します。

アクリル板叩いた位置ごとに異なる振動
→
KX134 / Solist-AI基板打撃検出・位置推論・ODL
→
Raspberry Pi画面表示・発音・カメラ・動画

通常の展示では、Windows PCやインターネットへの接続は必要ありません。ラズパイはUSB経由で推論結果を受け取ります。基礎モデルの再学習とファームウェアの更新には開発用PCを使います。

KX134-1211板の振動を取得する加速度センサ。取付状態を変えると振動特性も変わります。
DT-EBML63Q2557 / Solist-AI振動の特徴から60位置を推論。現場キャリブレーションもこの基板上で行います。

02 / HANDLING安全に使うために

  • 板・フレームを平らで安定した場所に置き、がたつきや緩みを確認します。板の上に体重をかけたり、物を置いたりしないでください。
  • 板にひび、欠け、大きな傷がある場合は使用を止めます。端面、固定具、センサ、ケーブルの取付部分は叩きません。
  • 指定のマレットで軽く叩きます。強い打撃や金属工具の使用は避けてください。反応しないときは接続や設定を確認します。
  • 配線・支持位置・センサの付け替えは電源を切ってから行います。ケーブルを張った状態で配置しないでください。
  • スピーカーの音量は小さい状態から調整します。飲み物や水分を電子基板の近くに置かないでください。
  • 再起動・電源断・データ削除・モデル書き込みは管理者が行います。来場者には演奏に必要な操作だけを案内します。

支持位置は認識精度に関係します。フレームへの固定やダンパーの状態を変えた場合は、まず12エリアを試奏し、必要なら現場キャリブレーションで補正します。

03 / SETUPセッティング（準備と接続）

3.1 用意するもの

  • アクリル板、ブラケット、固定用ボルト4本、フレーム、ダンパーバー、マレット、センサ、センサケーブル、Solist-AI基板
  • Raspberry Pi 4、対応する電源、セットアップ済みストレージ
  • モニター、対応するHDMIケーブル、モニター用電源、マウスまたはタッチ操作環境
  • スピーカーと音声ケーブル・電源（HDMI音声を使う場合は構成に合わせる）
  • データ通信対応のUSBケーブル、必要に応じてUSBカメラと固定具

3.2 アクリル板の取り付け

アクリル板はボルト4本でブラケットに固定します。取り付け後、センサと配線が演奏の邪魔にならないことを確認します。

ダンパーバーの上面がアクリル板と水平になるように、アクリル板とダンパーバーの設置角度を調節します。アクリルがダンパーバーに軽く押し付けられる状態が正常です。

カメラがアクリル板全体を視野に収められるように角度を調節します。取り付け後の映像表示と8点フィットは第6章を参照してください。

ラズパイを中心に、次のように各機器を接続します。機器間の配線を済ませてから、最後にラズパイのUSB Type-C電源端子へ給電します。

Solist-AI ⇔ 加速度センサ専用ケーブルで接続します。
ラズパイ ⇔ マウスラズパイのUSB Type-A端子へ接続します。
ラズパイ ⇔ カメララズパイのUSB Type-A端子へ接続します。
ラズパイ ⇔ モバイルモニターHDMI micro–miniケーブル。ラズパイ側がmicro HDMI、モバイルモニター側がmini HDMIです。
電源 → ラズパイ上記の配線後、ラズパイのUSB Type-C電源端子から電源を入力します。
加速度センサ ─ 専用ケーブル ─ Solist-AI │ USB Type-C USB A–Cケーブル │ USB Type-A ラズパイ ├ USB Type-A → マウス ├ USB Type-A → カメラ └ micro HDMI ─ HDMI micro–mini ─ mini HDMI │ モバイルモニター 最後に給電：電源 ─ USB Type-C → ラズパイの電源端子
  1. ラズパイとSolist-AIを、データ通信対応のUSB Type-A–Type-Cケーブルで接続します。
  2. Solist-AIと加速度センサを専用ケーブルで接続します。端子の向きは実機の表示と配線資料で確認します。
  3. マウスとカメラを、ラズパイのUSB Type-A端子へそれぞれ接続します。
  4. ラズパイとモバイルモニターをHDMI micro–miniケーブルで接続します。
  5. 配線を確認してから、ラズパイのUSB Type-C電源端子へ電源を入力します。起動後の確認は第4章へ進みます。

04 / POWER ON電源を入れて演奏する

  1. モニターとスピーカーを使える状態にし、スピーカーの音量を下げます。
  2. ラズパイへ電源を接続します。初期設定済みなら、デスクトップへの自動ログイン後に「演奏」画面が全画面で開きます。
  3. 画面右上が緑の「センサ接続中」になるまで待ちます。
  4. 画面を一度クリックまたはタッチします。ブラウザが音声の開始操作を求める場合に備えた操作です。
  5. 板のエリア中心を軽く叩き、音と表示が反応することを確認します。12エリアを順に確認し、音量を調整します。
  • 1「追加学習」：現場キャリブレーションへ移動します。普通に演奏するときは「演奏」のままで使います。
  • 2接続表示：「センサ接続中」を確認します。「センサ未接続」ならUSB配線を、「サーバ未接続」ならWebサーバーを確認します。

展示版は基板に接続できると自動的に演奏を開始します。PC用の通常画面では「接続」→「演奏開始」が必要です。付録Bを参照してください。

05 / PLAY演奏画面の使い方

板のエリアを叩くと推定されたエリアが反応し、そのエリアの音が鳴ります。画面のカメラ枠は、カメラが停止中でもエリアのグリッドとして使えます。表示中の確率やエリアは推論結果であり、必ず正しい位置を示すとは限りません。

音色・音量・曲を選ぶ

  • 1音色：スチールドラム、ピアノ、チェンバロ、ギター、ドラムから選びます。
  • 2音量：スライダーで調整します。大きな音を避けるため、スピーカー側も小音量から調整してください。
  • 3演奏補助：「自由演奏」または曲を選びます。曲を変えたら画面の音階・次のエリア表示を確認します。
  • 4音の長さ：発音の長さを調整します。長すぎて音が重なる場合は短くします。
  • 5曲の速さ：手本演奏・タイミング教示の速さを調整します。初めてなら遅めにします。
  • 6教示スタート：曲を選んで押すと、カウントダウンとタイミングの案内が始まります。示されたエリアをタイミングに合わせて叩きます。表示上の判定やコンボを目安に練習できます。
  • 7手本演奏：曲の手本を自動で鳴らします。もう一度押すと停止します。
  • 8最初から：曲の進行を先頭に戻します。曲をやり直すときに使います。

練習の順序

  1. 「自由演奏」で12エリアの場所と反応を確かめます。
  2. 曲を選び、「手本演奏」で旋律を聴きます。
  3. 手本を止め、案内されたエリアをゆっくり叩きます。
  4. 慣れたら「教示スタート」でタイミングに合わせます。難しいときは「曲の速さ」を下げます。

音が出ない場合は、第12章の「音が出ない」を確認してください。

06 / CAMERAカメラ映像の設定

カメラは板全体が見える位置に固定します。演奏者の手やマレットで板全体が隠れ続けない角度にしてください。映像の位置合わせは表示用であり、AIモデルの学習や精度そのものは変更しません。

  • 1カメラ：接続したUSBカメラを選びます。番号は接続環境により変わります。
  • 2カメラ開始：映像を表示します。通常ブラウザで許可を求められた場合は、この装置で使うカメラへのアクセスを許可します。
  • 38点フィット：映像内の板とエリア枠を合わせます。下記の順にクリックします。
  • 4フィット消去：位置合わせをやり直すときに使います。
  • 5停止：カメラを止めます。展示画面は定型グリッド表示へ戻ります。

8点フィットの手順

  1. 「カメラ開始」で板全体を映し、「8点フィット」を押します。
  2. 画面の指示に従い、左上 → 右上 → 右下 → 左下の順で板の四隅をクリックします。
  3. 続いて、左側の上段境界 → 右側の上段境界 → 左側の下段境界 → 右側の下段境界をクリックします。4×3のエリアを分ける、左右の端の2本の横境界です。
  4. 表示された枠が板と重なることを確認し、必要なら四隅と境界のハンドルをドラッグして調整します。
  5. 何か所か叩き、映像とエリア表示の対応を確認します。カメラを動かしたときは再調整します。

フィット設定はそのブラウザに保存されます。ブラウザの保存データを削除したり、別端末に移ったりした場合は合わせ直します。

カメラの取り付け位置と角度は、第3章「カメラの取り付け」の写真を参照してください。

07 / ON-DEVICE LEARNING現場キャリブレーション（追加学習）

設置し直した、固定の状態が変わった、マレットを替えたなどの理由で認識がずれるとき、Solist-AI基板上でモデルを調整します。これをODL（オンデバイス学習）と呼びます。新しい基礎モデルをPCで作る再学習とは別の操作です。

方式叩く場所展示画面の1回の操作使い方
高速12エリアの中心12打 × 5周＝60打まず短時間で設置の違いを補正するとき
精密中心12点＋四隅48点の60地点60打 × 5周＝300打中心以外も含めて調整するとき
  • 1高速：12中心点を案内します。
  • 2精密：60地点を案内します。
  • 3新たに5周を取り直す：基礎モデルから学習し直します。完了すると基板の保存済み校正を置き換えます。
  • 4追加学習（さらに5周）：基板に保存済みの校正を引き継ぎます。同じ方式の校正が保存されている場合だけ使えます。

学習を実行する

  1. 今の状態に戻したい場合は、下の「保存した重み」で先にバックアップします。
  2. 上部の「追加学習」へ移動し、「高速」または「精密」を選びます。
  3. 初めてなら「新たに5周を取り直す」、同じ方式の続きなら「追加学習（さらに5周）」を押します。
  4. 板の図で強調された地点を1回ずつ叩きます。受信が終わり、次の案内に変わってから次を叩きます。
  5. 5周終わり、「学習完了 — 保存しました」と表示されるまで待ちます。
  6. 「演奏」へ戻り、12エリアの中心とその周辺を試奏します。改善しなければ、保存した重みを戻すか初期モデルへ戻します。
  • 1指示とマーカー：実物の板で、その位置を叩きます。画面自体を押して学習する操作ではありません。
  • 2進行状況：周回数・打数を確認します。周ごとの判定は学習の進み具合の目安です。
  • 3中止（保存しない）：今回の作業を中止し、途中結果を保存しません。
  • 4一つ前へ戻る：誤った場所を叩いた場合に使います。画面が戻した地点を案内してから再度叩きます。

展示用画面は5周完了後に自動で保存します。前後の独立テストを比較して自動的に採否判定する画面ではありません。悪化した場合に備え、変更前の重みを保存してください。学習中はページ移動・USB取り外し・電源断を避けます。

校正結果を保存・復元する

  • 1保存名：会場・マレット・日付など、後から分かる名前を入力します。
  • 2現在の重みをこの端末に保存：基板の校正をラズパイ／PC側へ保存します。端末再起動後も残ります。
  • 3保存した重みの一覧：復元または書き出したい保存項目を選びます。
  • 4選んだ重みをボードへ戻す：選んだ校正を接続中の基板へ復元します。
  • 5選んだ重みをファイルに保存：JSONファイルとしてダウンロードし、別媒体へバックアップできます。
  • 6重みファイルを選んで読み込む：JSONを読み込み、端末に登録して基板へ復元します。読み込むだけで基板も変更される点に注意してください。
  • 7初期モデルに戻す：基板の保存済み校正を無効にし、基礎モデルに戻します。確認のため2回押します。

基板の有効な校正保存枠は1件です。複数の校正を残すときは端末側の保存とJSONを使います。基礎モデルが変わると重みの互換性がなくなる場合があり、CRCによる確認が行われます。

08 / DATA COLLECTION学習用データを採取する

基礎モデルを作り直すための振動データを、ガイドに従って収録します。ODLで保存した重みとは別のデータです。採取はラズパイでもWindowsでも行えます。ラズパイでは「管理」→「学習用データ採取」で開きます。

8.1 学習用と評価用を先に分ける

8.2 接続と保存先を設定する

  • 1板仕様：「400 × 300 × 5 mm（60位置・12エリア）」を選びます。図が4列×3行になることを確認します。
  • 2COMポート：実機のポートを選びます。WindowsはCOM番号、ラズパイは /dev/ttyACM* などです。
  • 3更新：USBを挿し直したときなどにポート一覧を読み直します。
  • 4接続：まだ接続していない場合に押します。別アプリがポートを使っている場合は閉じます。

  • 6保存先：用途別のフォルダを入力します。採取後に表示されるセッションIDも控えます。

8.3 中心と四隅を別々に採る

  • 1位置パターン：最初は「A: エリア中心 1点」、次のセッションで「B: 50 mm格子 四隅 4点」を選びます。
  • 2各位置の回数：学習用は50、評価用は10を入力します。
  • 3採取開始：ガイド収録を開始します。新しい採取runとして生成されたセッションIDと保存先を確認します。
  • 4採取停止：途中でやめる場合に押します。必要件数を満たした完成セットとして扱わないでください。
  • 5直前の1件を取り消して再測定：直前に誤った地点を叩いたときに使います。図の案内が戻ってから取り直します。
  • 6打点図：強調された点を叩き、受信と次の待ち受けを確認してから次へ進みます。回数・全体進捗を確認します。
  1. 実際に使う支持状態・マレットで設置し、周囲の衝撃や机への接触を避けます。
  2. 学習用の保存先で中心パターン・50回を収録します。各エリア50打、合計600打を確認します。
  3. 別の採取runで四隅パターン・50回を収録します。合計2,400打を確認し、中心と四隅の2セッションを1セットとして記録します。
  4. 評価用は別の保存先で中心・四隅を各10回収録します。合計600打を確認します。
  5. 日付、支持状態、マレット、採取者、用途、中心／四隅のセッションIDを記録します。

8.4 波形を確認し、バックアップする

  • 1セッション：確認する収録単位を選びます。イベント行を選ぶと下の波形・FFTに表示されます。

二重打撃、別の場所への打撃、机を叩いた振動、飽和した波形などを確認します。除外した場合は件数不足を記録し、必要なら取り直します。採取中の削除はできません。

保存されるのは各セッションの session.json、manifest.jsonl、manifest.csv、events/*.npz です。セッションフォルダごとバックアップし、これらをばらばらに編集しないでください。manifestの件数とイベント実数の不整合は学習時の読込エラーになります。

9.2 学習環境とデータを準備する

  1. 開発PCにリポジトリ、Python環境、requirements.txtの依存パッケージを用意します。ファーム更新には別途LEXIDEのベンダープロジェクト、ビルドツール、MCU-Linkが必要です。

9.3 新しい候補モデルを学習する

次は、採取したデータで128–32–60の候補を作る汎用コマンドです。リポジトリ直下で実行します。pythonは依存パッケージを導入済みのPythonに置き換えてください。最初は出力を候補フォルダへ置き、搭載用ファイルを直接上書きしません。

python -m sim.device_position_probability --sessions data/raw/manual_training --session-ids all --output-dir artifacts/manual_candidate/device_position --header artifacts/manual_candidate/apan_position_probability_model.h

出力は model.npz、training_report.json、指定したモデルヘッダーです。処理内では反復番号を使う内部評価を行った後、選んだ学習データ全件で最終候補を学習します。内部評価の結果だけで独立評価の代わりにしないでください。

最新配備モデルを厳密に再生成する場合
最新24,000打版は scripts/capacity_comparison.py → scripts/capacity_add_t8.py の実験系列で生成され、160エポック・蒸留比率0.25の設定を使用しています。上の汎用CLIは同じ構造の候補作成手順で、配備バイナリをそのまま再現する保証はありません。厳密な再現には、配備時のデータ、特徴キャッシュ、学習条件をそろえ、生成スクリプトと配備記録を照合します。

9.4 独立データで比較する

python -m sim.evaluate_device_model --model artifacts/manual_candidate/device_position/model.npz --sessions data/raw/manual_evaluation --session-ids all > artifacts/manual_candidate/independent_evaluation.json

現在使用中のモデルにも同じ評価セッションを入力し、60位置Top-1、12エリア精度、平均距離誤差、25 mm以内率、地点別の失敗傾向を比較します。学習レポートの session_ids と評価用IDに重複がないことを確認します。悪化した候補は配備せず、収録条件・誤ラベル・データ偏りを見直します。

9.5 モデルとODL初期行列を反映する

採用後に、候補モデルに対応するODL初期行列を生成します。学習時と同じセッションを指定します。

python -m sim.position_odl_calibration_prior --sessions data/raw/manual_training --session-ids all --model artifacts/manual_candidate/device_position/model.npz --prior-header artifacts/manual_candidate/apan_calibration_prior.h
  1. 採用した apan_position_probability_model.h と apan_calibration_prior.h を、両方とも firmware/AcrylicPanCollector/generated/ へ反映します。モデルと初期行列を別世代で混ぜません。
  2. Windowsの開発環境でクリーンビルドします。下のパスは実際のベンダープロジェクトへ置き換えます。
.\scripts\build-firmware.ps1 -SourceProject <LEXIDEのベンダープロジェクト> -Clean
.\scripts\flash-firmware.ps1 -FirmwareHex <ビルドで生成されたHEX> -Execute

書き込み前にWebサーバーなどのポート使用を止め、対象基板とMCU-Linkの接続を確認します。ビルド結果のリンクマップに ApanCollectorAppInitialize と apan_position_beta が入り、βとCRCが意図した候補に一致することを確認します。

9.6 更新後の確認と復旧

  • 書き込み・照合が成功し、基板を再起動できる。
  • USB接続、演奏、12エリア反応、音声が動作する。
  • 新しい基礎モデルでODLの開始・中止・保存ができる。
  • 電源を入れ直しても基礎モデルと有効な校正が意図どおり使われる。
  • モデル、データID、評価JSON、ヘッダー、CRC、Gitコミット、HEX/ELFをまとめて保存した。

問題があれば保存した動作確認済みのHEXを書き戻します。ソースを戻すだけでは基板は戻りません。モデルのCRCが変わると既存校正が無効になるため、復旧・更新後は校正状態も確認します。

10 / EXHIBITION展示で使う

開場前の点検

  • 配線が抜けかけていない。板・フレーム・センサに緩みがない。
  • 電源投入から演奏画面まで自動で立ち上がる。
  • 12エリアで発音と表示を確認し、適切な音量になっている。
  • カメラを使う場合は映像とフィットが合っている。
  • 管理画面の必須項目に赤がない。黄色は内容を読み、使用する機能に問題がない。
  • ネットワークなしでも、演奏・音声・必要な動画が使える。

デモ動画を見せる

上部の「デモ動画」で再生画面へ移動します。動画を出るときは「演奏」へ戻ります。動画はラズパイ上の web/assets/pv/ のMP4を使います。別フォルダはサーバーの --video-dir で指定できます。

  • 1再生・一時停止：動画を再生／停止します。自動再生されないときもこのボタンを押します。
  • 2シークバー：見せたい位置へ移動します。
  • 3リピート：複数本では全リピート・1本リピート・リピートなしを切り替えます。1本だけの場合は1本リピート／なしです。

管理画面で点検する

  • 1自動検査を実行：開いたときの自動検査を、必要に応じてやり直します。
  • 2学習用データ採取：第8章の収録画面を開きます。
  • 3展示に必要な項目：通信、入力、音声などを確認します。赤があれば、各項目の対処内容を確認します。
  • 4保守・オプション：カメラや遠隔保守などです。未使用の任意機能は黄色でも展示できる場合があります。

KX134の実打確認には、板を叩いて取得した推論結果が必要です。固定入力の自己診断だけでは合格になりません。演奏中の検査は演奏を止めず直近の状態を使うため、完全な通信往復検査が必要なら演奏を停止して再検査します。

「管理」タブは来場者にも見えるため、管理操作を来場者に任せないよう配置・運用を決めます。展示中のプログラム更新やファーム書き込みは避け、変更後は開場前の点検をやり直してください。

11 / SHUTDOWN終了と保管

  • 1Web UIを再起動：Webサーバーだけを再起動します。画面の不調への対処に使います。
  • 2ラズパイを再起動：OS全体を再起動します。終了して持ち帰る操作とは異なります。
  • 3ラズパイの電源を切る：使用を終えるときに3秒間長押しします。
  1. 採取や追加学習を完了または中止し、必要なデータを保存します。
  2. 「管理」を開き、「ラズパイの電源を切る」を3秒間長押しします。
  3. 画面の終了案内を確認します。OSの終了とストレージのアクセスLEDの点滅停止を確認してから電源を外します。
  4. 周辺機器の電源を切り、コネクタを持ってケーブルを外します。
  5. 板を柔らかい布で清掃し、センサや端子を保護して運搬します。アクリル対応が確認できない溶剤は使わないでください。

追加学習・収録中はシステム操作が無効になります。反応がない場合は、第12章の確認を行ってください。

12 / TROUBLESHOOTING困ったときは

症状順に確認すること
演奏画面が開かない電源・モニター入力を確認。ラズパイのDesktop Autologin、自動起動サービス、ブラウザ自動起動を付録Aで確認します。
「サーバ未接続」管理画面へ接続できるか確認。端末で systemctl status acrylic-pan-exhibit とログを確認します。
「センサ未接続」通信対応USBケーブル、基板の給電、接続先ポートを確認。別のアプリが同じシリアルポートを使っていないか確認します。
音が出ない画面を一度操作。音量スライダー、スピーカー電源・音量、OSのHDMI／3.5mm出力先、ブラウザのミュートを確認します。「手本演奏」でも無音か切り分けます。
音は鳴るが場所が違う板の向き・支持位置・マレットを確認。曲を選ぶと音の割り当てが変わります。自由演奏で確認し、必要なら第7章のODLを行います。
連打がうまく検出されない強打をやめ、打撃を少し離して確認。固定部の緩み、板の残留振動、ケーブルが板へ触れていないか確認します。
カメラが映らないUSB接続、カメラ選択、「カメラ開始」、ブラウザの許可を確認。他アプリでカメラを使用していれば閉じます。
映像とエリア枠がずれるカメラの固定を確認し、「8点フィット」をやり直します。AIモデルの再学習は不要です。
追加学習ボタンが無効「さらに5周」は同方式の保存済み校正が必要です。初回や方式変更時は「新たに5周を取り直す」を使います。
追加学習後に悪化した取り違えた打点がないか確認。保存していた重みを復元するか、「初期モデルに戻す」で基礎モデルを確認します。
デモ動画がないラズパイ内の web/assets/pv/ にMP4があるか確認。ページ上の再生ボタンも押します。
採取データをPCで見つけられないサーバーが動いた端末の保存先を確認。ラズパイ上の保存データは第8章の方法でPCへコピーします。
学習データの読込で失敗セッション完了状態、板仕様、イベント数、manifest整合性を確認。バックアップからフォルダ単位で復元します。
管理画面の電源断が失敗ラズパイ用の管理ヘルパーの導入状態を確認。Windows上の画面ではラズパイの電源断はできません。

解決しない場合は、発生時刻、操作、画面表示、基板・マレット・設置条件、ログを記録して保守担当者へ伝えます。確認中に収録データを削除したり、無関係な設定をまとめて変更したりしないでください。

USBシリアル機器が複数ある場合はサービスの --auto-connect に対象機器の固定パスを指定します。設定変更後はsystemdの再読込・サービス再起動と接続確認を行います。キオスク表示を閉じる場合はキーボードの Alt+F4 を使います。

コード更新時は変更前の状態を保存し、git pull --ff-onlyの後にサービスを再起動して点検します。ソースを更新するだけでは基板のファームウェアは更新されません。遠隔保守が必要な場合は詳細セットアップ資料を参照してください。

APPENDIX B / WINDOWSWindows PCで使う

Windowsでも同じ基板を接続し、通常の楽器画面や採取画面を使用できます。以下はリポジトリ直下のPowerShellで実行する例です。Pythonの場所は導入した環境に合わせます。

B.1 通常の楽器画面

.\scripts\run-monitor.ps1 -Python C:\ProgramData\anaconda3\python.exe -Page instrument-probability.html
  1. ブラウザで http://127.0.0.1:8765/instrument-probability.html を開きます。
  2. 板仕様「400 × 300 × 5 mm」、実機のCOMポートを選びます。
  3. 確率推論元を「デバイス（Solist-AI・60クラス）」にして「接続」→「演奏開始」を押します。
  4. 採取するときは「学習データ採取」タブへ移動し、第8章に従います。

COM番号はPCごとに違います。固定のCOM3を前提にせず、ポート一覧やデバイスマネージャーで確認してください。停止は起動したPowerShellで Ctrl+C です。

B.2 展示画面を試す

リポジトリの .venv\Scripts\python.exe に依存が導入済みなら次を使えます。

# 実機を使う
.\scripts\run-exhibit.ps1
# 基板なしで追加学習などの画面を試す（実際の学習・認識の評価には使わない）
.\scripts\run-exhibit.ps1 -FakeBoard

展示画面は http://127.0.0.1:8765/exhibit/play.html です。同じポートで2つのサーバーを同時に起動しないでください。

B.3 本番用プレゼンテーション

.\scripts\run-presentation.ps1 -Python C:\ProgramData\anaconda3\python.exe

メイン：http://127.0.0.1:8780/presentation/index.html
発表者：http://127.0.0.1:8780/presentation/presenter.html

→で次へ、←で前へ、Fで全画面、Pで発表者画面を開きます。プレゼン内の楽器デモを使う場合は、8765番の楽器サーバーも起動します。

公開マニュアルと実機UIの違い
GitHub Pagesにあるこのページは静的な説明書です。ここから基板へ接続したりラズパイの電源を操作したりはしません。実機操作には、装置上で動くPythonサーバーとそのローカル画面を使います。
