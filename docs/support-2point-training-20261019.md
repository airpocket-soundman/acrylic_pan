# 2点支持への変更と、学習の結果(2026-10-19)

## 背景

これまでの固定(1点支持)では、振動が長く続き、連打すると誤検知が出た。ボードの固定を2点支持に変更し、
学習用データを採取し直している。1点支持のモデル一式は `models/support-1point/` に保存した
(`python scripts/model_snapshot.py restore support-1point` で戻せる)。

2点支持のデータは `data/raw/sessions_2point/` に置く。

## 使ったデータ

採取が終わっている4セッション、2,640打。

| セッション | 種類 | 回数 | 打数 |
|---|---|---:|---:|
| `20261019_205614_7b39e09d` | センター(12エリア中心) | 50 | 600 |
| `20261019_210631_9e9fd28a` | センター | 50 | 600 |
| `20261019_211259_81afc894` | 四隅(48点) | 10 | 480 |
| `20261019_211815_650952aa` | 四隅 | 20 | 960 |

採取中のセッションが混ざらないよう、セッションを指定して学習した。

## 結果

出力は `artifacts/support-2point-partial/` に置いた。ファームのモデルヘッダー(`firmware/.../generated`)は書き換えていない。

### 1点支持の旧モデルは、2点支持の板では使えない

旧モデル(60位置)を、2点支持のデータ2,640打で評価した。

| 区分 | 位置の正解率 | 12エリアの正解率 | 期待座標の平均誤差 |
|---|---:|---:|---:|
| 全体 | 24.3% | 37.8% | 121.2 mm |
| センター | 29.0% | 42.4% | 116.5 mm |
| 四隅 | 20.3% | 34.0% | 125.2 mm |

固定方法の変更で、振動の出方が大きく変わっている。再学習が必要である。

### 2点支持で学習し直したモデル

学習時の検証は、反復番号が5の倍数の打撃を除いて学習する、同一セッション内の分割で行った
(1点支持のときと同じ方法)。**同じ固定で取ったデータでの値であり、別のセッションでの精度ではない。**

| モデル | 指標 | 値 |
|---|---|---:|
| 60位置(Solist-AI 128-32-60) | 位置の正解率 | 97.2% |
| | 期待座標の平均誤差 / 中央値 | 6.78 mm / 0.99 mm |
| | 25 mm 以内の割合 | 95.3% |
| 12クラス | 正解率 | 90.2%(センター 100%、四隅 81.9%) |

### 別セッションでの精度(12クラス、セッションを丸ごと学習から外した評価)

| 学習から外したセッション | 正解率 |
|---|---:|
| センター#1 | 97.7% |
| センター#2 | 99.2% |
| 四隅#1(10回) | 74.6% |
| 四隅#2(20回) | 72.8% |

センターは、別セッションでも 97〜99% である。四隅は、学習に使える四隅のセッションが1つしかない状態で
72〜75% であり、1点支持のときの、四隅7セッション学習での約 84% を下回る。四隅のセッションを増やすことで改善する。

## 再現

```powershell
python -m sim.device_position_probability --sessions data/raw/sessions_2point `
  --session-ids <セッションIDのカンマ区切り> `
  --output-dir artifacts/support-2point-partial/device_position `
  --header artifacts/support-2point-partial/apan_position_probability_model.h

python -m sim.train_max_data_12class --sessions data/raw/sessions_2point `
  --session-ids <セッションIDのカンマ区切り> `
  --output-dir artifacts/support-2point-partial/class12 `
  --header artifacts/support-2point-partial/apan_12class_model.h

python -m sim.evaluate_device_model --model <model.npz> --sessions <セッションの置き場> --session-ids <...>
```

`--session-ids` は、`default`(1点支持の11セッション)、`all`(終了済みの全セッション)、またはカンマ区切りで指定する。

## PC側のモデルの学習し直し(5セッション)

2点支持の5セッション、3,600打で、PC側の60位置の確率マップモデル(`sim.pc_position_grid_runtime`)も学習し直した。
旧(1点支持)のモデルは `models/support-1point/` に保存済みで、`artifacts/pc_position_runtime_400x300x5/` には、2点支持のモデルを入れた

## ODL画面の「認識テスト」と「教示演奏テスト」

クラス演奏ページのODL画面で、学習も保存もせずに、いまのモデルの認識を調べられる。

- **認識テスト**: 12エリアを順に叩き、正解率、エリア別の正解数、間違えやすい組を出す。叩くたびに、認識したエリアの音が鳴る。
- **教示演奏テスト(マリオ)**: マリオ(地上BGMの前半: 冒頭の1小節と、主要なフレーズの2回、41音、手本で約8秒)を、次に叩くパネルが光る教示で演奏する。各音が正しいエリアとして認識されたかを数える。
  どのエリアを叩いても、次の音へ進む。

教示演奏のマリオは、16分音符を単位にした譜面(冒頭 `E5 E5 E5 C5 E5 G5 G4`、続けて `C5 G4 E4 A4 B4 A#4 A4`、
`G4 E5 G5 A5 F5 G5 E5 C5 D5 B4`、その2回目)で、D5 と F5 を含む。そのため、音の割り当ては、既存の「mario」(D5・F5 が無い)ではなく、
曲専用の「マリオ(教示用)」(E4 G4 A4 A#4 B4 C5 D5 E5 F5 G5 A5 C6)に切り替わる。「mario」の割り当ては、そのまま残る。
