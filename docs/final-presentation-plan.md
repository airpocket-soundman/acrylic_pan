# 決勝審査会プレゼン資料(Webアプリ)のタスクと設計

ROHM Edge Hack Challenge 2026の決勝審査会用に、ブラウザで動く発表資料を作る。発表時間は質疑を除いて5分。
実装は `web/presentation/` にある。

## タスク

| ID | タスク | 内容 |
|---|---|---|
| P1 | メイン画面 | スライド風のページを全画面で表示する。キー操作とクリックでページを送る |
| P2 | プレゼンター画面 | 別ウィンドウで開き、セカンド画面に置く。現在・次のスライド、ノート、タイマー、スライド一覧を出す |
| P3 | 同期 | メインとプレゼンターのページ送り・タイマーを同期する |
| P4 | 内容 | 下記の構成で、リポジトリ内の図表・PV・評価レポートの数値だけを使って作る |
| P5 | ライブデモ | 2枚目に楽器のWebUIを埋め込み、ヒートマップ・疑似XY座標・音色変更・音楽教示を操作しながら説明できるようにする |

## スライド構成(10枚。ライブデモ5分+ほか3分50秒)

発表の流れは、外観とひとこと → 楽器のWebUIでデモ → 「なぜセンサ1個で位置がわかるか」「E2Eの符号化と復号」 → 二つのテーマ(楽器兼ゲーム/エッジAI研究) → ELMの小ささの比較 → 詳細、とする。「ゲームとして」のスライドはない(デモで見せるため)。二つのテーマのスライドは、右矢印で、①、②の順にフォーカスが移る(選ばれた側が明るく浮き上がり、ほかは暗くなる)。

| 2 | ライブデモ | 導入の4場面(カメラ映像、スチールパン、しくみ、デモの画面)のあと、ヒートマップ、疑似XY座標、音色変更、音楽教示を説明しながら演奏する | 300 s |

## 設計

- 静的なWebアプリ(HTML/CSS/JS、外部ライブラリなし)。`web/presentation/index.html` がメイン、`presenter.html` がプレゼンター。
- スライドの内容・ノート・目安時間は `slides.js` の1か所に置き、メインとプレゼンターの両方が読む。
- 画面間の同期は `BroadcastChannel` で行い、使えない環境では `localStorage` のイベントで代替する。同じオリジンで開く必要があるため、
  `file://` ではなく、`scripts/run-presentation.ps1` が起動するローカルHTTPサーバー、または公開ページから開く。
- メイン画面は固定の1920×1080のステージを画面に合わせて拡大縮小する。`F` キーまたはボタンで全画面にする。
- プレゼンター画面は、メインの「プレゼンターを開く」から開く。ブラウザがマルチスクリーン対応(Window Management API)なら
  セカンド画面へ自動配置し、対応していなければウィンドウを手でドラッグして置く。
- 2枚目のデモは、スライドの飾りを置かず、演奏画面そのものを全面に表示する。PC上の楽器サーバー(既定 `http://127.0.0.1:8765/instrument-probability.html?embed=1`)の確率演奏ページを `iframe` で表示する。`embed` は、メイン画面からの指示(自動演奏・プレゼンターの操作)を受け付ける指定で、ページの見た目は元のままである。`&bare=1` を足すと、ヘッダーとモード切替のタブを隠す。埋め込み時は、ヘッダーの説明・タブ・状況バーを畳んで3列に並べる「全体表示」にして、1920×1080に縦もちょうど収める(`&nofit=1` で元のレイアウト)。楽器ページは、1920×1080の大きさに固定して、スライドと同じ倍率で拡大縮小する。音は、楽器ページではなく、キー操作を受けるメイン画面が鳴らす。
  URLはプレゼンター画面で変更できる。サーバーが動いていないときは、PVの映像へ切り替えられる。
- **2枚目(デモ)の4つの場面**: 右矢印で、同じスライドの中の場面が順に進む。
  1. 背景は、デモの画面のカメラ映像の大写し(デモの画面を拡大し、カメラ映像の部分だけを全面に映す。
     カメラは同時に2か所で開けないため、デモの画面自体を拡大している)。大写しの間は、8点フィットの表示(グリッド・エリア表示・ハンドル)、ヒートマップ、操作パネル、背景を、すべて隠す
  2. スチールパンの写真(`web/assets/presentation/steelpan.jpg`)が、ゆっくり重なる。出典「Photo: Terry Ballard / CC BY 2.0 (Wikimedia Commons)」を、スライドの右下に表示する(`THIRD_PARTY_NOTICES.md` にも記載)
  3. スチールパンが消える
  4. カメラ映像だけが、デモの画面の元の位置へ縮んで移る(1.3秒)。動きが終わってから、フィットの表示を含む他のUI(操作、確率、ヒートマップ)が、フェードインする
  5. 画面が現れたあと、右矢印で、カードを1枚ずつ説明する。説明中のカードは少し拡大して浮き上がり、ほかは暗くなる(`spot`)。順に、上部の設定カード(板仕様・COMポート・接続)、12エリア確率、最下段(音色・音量・曲・音の長さ・手本演奏)、カメラ。
     最下段のカードの場面に入ると、接続と演奏開始をして、曲「エリーゼのために」を選ぶ。カメラのカードの説明は、その曲を弾きながら行う(2小節ほど)。最後の場面で演奏を止める。
     音色と音量は、最下段のカードに置いた。
  デモのスライドの持ち時間は5分(300秒)で、デモの各場面の台詞と秒数は、プレゼンター画面に出る。
  最後の場面のあとの右矢印で、次のスライドへ進む。
  場面は、プレゼンター画面のステップと連動し、台詞も、そこに出る。
- **デモの自動演奏とリモート操作**: デモのスライドに入ると、メイン画面が楽器ページへ「接続 → 演奏開始」を自動で指示する
  (`postMessage`)。埋め込み時(`?embed=1`)の楽器ページだけが、信頼できるローカルのオリジンからの指示を受け付ける。
  プレゼンター画面には「演奏開始/停止」「手本演奏」「音色」「曲」「音量」の操作と、接続・演奏中の状態表示がある。
  デモのステップに入ると、そのステップの操作(例: 音楽教示のステップで曲を選ぶ)が自動で実行される。
  自動実行は、プレゼンター画面のチェックで切れる。メイン画面のキー `S` で演奏の開始/停止を切り替えられる。
  ブラウザの音声は、メイン画面を一度クリックまたはキー操作してからでないと出ない。
- **デモ画面の状態の維持**: 楽器ページ(`iframe`)は、スライドの外側に1つだけ置き、他のスライドを開いても破棄しない
  (表示だけを切り替える)。接続、演奏の開始/停止、音色や曲の選択、カメラの設定や位置合わせは、スライドを行き来しても保たれる。
  自動演奏は、デモのスライドを最初に開いたときだけ実行し、2回目以降は状態をそのままにする。
  メイン画面のページを再読み込みすると楽器ページも読み込み直されるため、本番中は再読み込みしない。
- キー操作: `→`/`Space`/`PageDown` 次へ、`←`/`PageUp` 前へ、`Home`/`End` 先頭・末尾、`F` 全画面、`B` 画面を黒にする、
  `P` プレゼンターを開く。

## 数値の扱い

- 実機搭載モデル(Solist-AI 128-32-60)は、60位置の正解率97.9%、期待座標の平均誤差5.5 mm(中央値0.6 mm)、25 mm以内95.6%。
  学習に使わない720打点での評価だが、同一収録セッション内の分割であり、スライドにもそう明記する。
- ODLの効果は、実機で、マレットをサインペンに替えて、各エリア5打(60打)のODLの前後に120打ずつ評価し、60.0% → 95.0%(スライドには、この数字と条件だけを載せる。[記録](odl-mallet-experiment-20261020.md))。
  悪化したときは保存せず元に戻す。対象は12クラスのモデルで、60クラス側は対象外とスライドにも明記する。
