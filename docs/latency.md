# 打撃から発音までのレイテンシ

打撃から音が出るまでの経路と、各区間の遅延、短縮のために入れた対策をまとめる。

## 経路と遅延

| 区間 | 遅延 | 内容 |
|---|---:|---|
| 打撃検出 | 約0.6 ms | 隣接サンプル差がしきい値を超え、0.625 ms 以内に大振幅が来たら確定 |
| 波形の取り込み | 17.5 ms | トリガ後448点(25.6 kHz)。モデルの入力が、この区間から128点を取る |
| Solist-AI推論 | 再実測が必要 | 60出力の単一ヘッドを1回実行。旧5ヘッドと全logit一致をシミュレーターで確認済み |
| softmax(60位置のみ) | 約2 ms | ボード上の整数演算(Q27のロジットと3つの指数テーブル)。float32の `expf` との最大絶対誤差は約3e-8。60位置の推論とsoftmaxの合計は約22.7 ms |
| UART送信 | 約0.1〜3 ms | 960 kbit/s。115200 bit/s では、12クラスで約5 ms、60位置(256 byte)で約24 ms |
| USB-シリアル | 最大 約16 ms | FTDIのLatency Timer(既定16 ms)。下記の設定で1 msにできる |
| PCの受信 | 約0 ms | 先頭1バイトで起き、届いている分をまとめて読む |
| サーバー | 約0.1 ms | 確率から座標・エリア確率を計算 |
| ブラウザへの配信 | 約1 ms | `/api/ai/wait` のlong-poll。新しい結果が来た瞬間に応答する |
| 音の再生 | ブラウザとOSの出力バッファによる | 音はあらかじめ取得・デコード済みのサンプルを、即時に再生する |

## 入れた対策

| 対策 | 効果 |
|---|---|
| 受信を `read(4096)`(50 msタイムアウト)から「先頭1バイトで起きて残りをまとめて読む」方式へ | 往復 約57 ms → 約12 ms。小さな結果フレームが最大50 ms滞留していた |
| 書き込みを、受信スレッドの待ちに依存せず、呼び出した側で即時に行う | コマンドの送信遅延を除去 |
| 起動後に、UARTを115200 → 960 kbit/s へ自動で切り替える(`SET_CONFIG` のキー `0xB1`、分周値3) | 60位置の結果の送信 約24 ms → 約3 ms。電源を入れ直すと115200に戻る |
| 位置確率のsoftmaxを、float32の `expf` から整数演算とテーブルへ(推論はボードで完結) | 約13.8 ms → 約2 ms |
| クラス演奏ページを、20 ms周期のpollingから `/api/ai/wait` のlong-pollへ | 平均10 ms、最大20 msの待ちを除去 |
| 音声出力から、DynamicsCompressor(約6 msの先読み)を外し、遅延のないソフトクリッパーへ | 約6 ms |
| 音声を先に再生し、画面の更新は後にする | 画面の描画ぶんの遅延を除去 |
| 音声コンテキストを最小遅延(`latencyHint: 0`)で作る | 出力バッファぶん |

## FTDIのLatency Timer(PC側の設定)

DT-EBML63Q2557のUSB-シリアルはFTDI(FT2232H、VID 0403 / PID 6010)で、
Latency Timerの既定値は16 msである。数十バイトの結果フレームは、バッファが埋まらないため、
このタイマーが切れるまでPCへ送られない。1 msにすると、打撃ごとに平均で約8 ms短くなる。

1. デバイスマネージャー →「ポート(COMとLPT)」→ 該当の `USB Serial Port (COM3)` →「プロパティ」
2. 「ポートの設定」→「詳細設定」→「Latency Timer (msec)」を `1` にする
3. USBを抜き差しする

## 取り込み時間の短縮と精度

波形の取り込み(17.5 ms)は、現在の最大の固定遅延である。取り込みを短くするには、モデルを短い区間で学習し直す必要がある。
12エリアの正解率を簡易ELM(128-32、隠れ層32)で比べた見積もりでは、次のとおり。

| トリガ後の点数 | 時間 | 正解率(12エリア、反復番号で分けた評価) |
|---:|---:|---:|
| 448(現行) | 17.5 ms | 81.4% |
| 320 | 12.5 ms | 79.9% |
| 256 | 10.0 ms | 78.5% |
| 224 | 8.8 ms | 72.2% |

この値は簡易モデルの相対比較で、実機モデルの精度ではない。短縮すると、取り込みの短縮ぶんだけ精度が下がる。
